# 题卡能力交接文档（2026-05-08）

## 1. 当前已实现能力

### 1.1 Agent 题卡动作（已跑通）
- `create`：创建新题目卡片。
- `insert`：按锚点卡片（`anchorCardID`）在前/后插入新题目卡片。
- 已支持中文题干通过 CLI 写入（避免 Windows 控制台编码导致乱码）。

### 1.2 后端能力面与写入链路
- 题卡主链路已围绕 `StudioDocument -> StudioQuestionCard` 工作。
- 已提供并使用题卡内部门面（`internal-api` / service）执行 create/insert。
- 已支持变更事件发布（`studio.cards.changed`），包含 `reason`、`cardIDs`、`revision` 等信息。

### 1.3 前端展示与即时更新
- 题卡页可在不手动刷新页面的情况下看到 create/insert 结果（已打通事件驱动刷新）。
- 插入动作的题卡高亮动画已恢复，并已修复“动画不自动停止”的问题。

## 2. “代码掌控一切”思路与设计落地

## 2.1 核心原则
- Agent 以“执行面”为核心：可运行命令、可写代码、可调用项目内能力。
- 不为每个业务动作额外发明一套前端函数工具。
- 不要求用户理解 `documentID/workset` 等内部概念。

## 2.2 本次采取的基础设施形态
- 采用 **project-native command bridge**：
  - Agent 仍走 CLI/命令式执行体验。
  - CLI 不直接“猜路径/猜文件”，而通过后端桥接到项目内题卡能力。
  - 写入与事件发布统一在主后端进程内完成，避免多进程状态分裂。
- 结果：Agent 仍然“像 CLI 一样工作”，但数据一致性由后端主链路保证。

## 2.3 对 UI 状态的定位
- UI 不是执行前提，只是回显层。
- 用户是否正在题卡标签页，不影响 create/insert 可执行性。
- 当用户回到题卡页时，应看到最新容器真相。

## 3. 本阶段解决的问题

- 解决了“工具执行成功但前端看不到变更（需刷新）”的主问题。
- 解决了 insert 语义与锚点插入行为对齐问题。
- 解决了 Windows 中文输入在 CLI 调用链中的乱码问题。
- 解决了题卡插入动画可触发但不停止的问题：
  - 根因是前端 `React.memo` 比较遗漏 `uiState`，导致清理状态不触发重渲染。

---

## 4. AG-UI 协议技术决策

## 4.1 决策结论
- **当前“出题（create/insert）场景，不再依赖 AG-UI 协议作为主路径。**
- 原因：该场景核心是“数据写入成功 + UI及时刷新 + 轻量动画反馈”，用后端事件流即可稳定达成。

## 4.2 是否放弃 AG-UI
- 否。AG-UI 保留为后续复杂交互场景的候选机制，尤其是：
  - 讲解过程中的多步骤可视状态机。
  - 图像/区域级讲解、富交互引导。
- 但在当前题卡出题链路上，强行引入 AG-UI 会增加复杂度，收益不成正比。

## 5. 仍存在的问题（未完成）

1. CLI 工具调用时的 LLM 缓存策略尚未探索（命中键、过期策略、去重边界未定）。
2. 题目卡片背后的学习数据结构未完成设计（学习轨迹、掌握度、诊断状态等）。
3. 题目质量体系未建立（生成质量评估、约束、校验与回收机制缺失）。
4. 题型维度未设计（选择、填空、解答、阅读、变式等统一 schema 未定义）。

## 6. 当前阶段结论

- 当前已跑通 `insert` 与 `create` 的动作执行和动画回显。
- 系统状态可定义为：**Demo 级可用**。
- 距离可长期稳定的生产级能力仍有关键基础设施与数据建模工作待完成（见第 5 节）。
